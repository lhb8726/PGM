**개인 성장 플랫폼 — 요구사항 및 개발계획 초안 v0.1**

작성 기준: 2026-11-03, 사용자 요구와 추가 답변 반영. 이 문서는 개발 전 검토할 설계 초안이며, 실행 프로그램을 구현하거나 기능을 시험한 결과가 아니다. 기술 특성에 관한 사실은 해당 문장에 공식 출처를 연결했다. 기능 구성·우선순위·평가 방식은 설계 제안이며, 개인의 역량을 객관적으로 검증한 평가 모델이라는 뜻은 아니다.

**사용자가 정한 범위는 다음과 같다.**

| 항목 | 요구사항 |
|---|---|
| 목적 | 현재 상태를 파악하고 목표까지의 성장 경로를 설계·실행·수정하는 개인용 플랫폼 |
| 사용 환경 | Windows 및 macOS |
| 사용·배포 | 개인 PC용, 별도 온라인 배포 불필요 |
| 기기 간 데이터 이동 | 백업 파일을 내보내고 다른 기기에서 복원 |
| 인터넷 | AI와 자료 검색에 사용 허용 |
| 개발 | 1인 프로젝트, 익숙한 언어 Python |
| 목표 | 자산·취업·자기개발 등을 카테고리로 관리, 단기·중기·장기 목표 지원 |
| 완료 기준 | 설정한 수치·성과 달성, 자격증 취득, 포트폴리오 완성 등 |
| 화면 참고 | 첨부 이미지의 어두운 테마, 왼쪽 탐색 메뉴, 카드형 지표와 목표 진행 표시 |

**제품의 핵심은 현재 상태와 제약을 반영해 실행 가능한 경로를 제안하는 것이다.**

기본 흐름은 `현재 상태 입력 → 진단 근거 확인 → 목표·제약 설정 → 경로 제안 → 월·주·일 계획 → 실행·회고 → 상태 갱신·재계획`으로 둔다.

‘최적 경로’는 사용자가 선택한 우선순위와 시간·예산·기한 안에서 비교하고 설명할 수 있는 추천 경로로 정의한다. 사용자의 선호와 가용 자원, 필요한 선행 역량이 없으면 최적이라고 판단할 정보가 부족하다. 추천 결과에는 반영한 조건, 예상치, 부족한 정보, 대안과 선택 이유를 표시한다. 취업·합격·수익·건강 개선의 확률을 근거 없이 수치로 만들어 제시하지 않는다.

장기 목표의 큰 방향을 잡은 뒤 가까운 기간의 계획부터 상세화한다. 먼 미래의 일정을 모두 일 단위로 확정하는 방식은 피하고, 실행 기록과 조건 변경을 반영해 다음 기간의 계획을 구체화한다.

**6개 분야는 공통 엔진 위에 분야별 입력과 판정 기준을 붙인다.**

| 분야 | 현재 상태 입력 예시 | 목표·성과 지표 예시 | 진단에 사용할 근거 예시 |
|---|---|---|---|
| 금융 및 자산 관리 | 자산·부채·수입·지출, 기준일, 통화, 투자 지식 자기평가 | 목표 순자산, 월 저축액, 현금흐름 변화 | 사용자가 확인한 금액·명세, 지식 문항 응답 |
| 커리어 및 전문성 | 직업·경력·기술·자격증·기존 프로젝트 | 자격 취득, 결과물 완성, 지원 준비 기준 충족 | 자격증, 프로젝트, 평가 기준표, 확인한 채용 요건 |
| 학습 및 지식 | 학습 이력, 시험 결과, 수준, 주당 학습 시간 | 점수·문제 해결·독서 기록·학습 결과물 | 시험·문제 풀이 결과, 제출한 결과물 |
| 건강 및 체력 | 운동·수면 기록, 측정한 체력 지표, 활동 제약 | 운동 빈도·기록, 수면 습관, 사용자가 정한 측정 목표 | 사용자 기록과 측정값 |
| 경험 및 라이프스타일 | 관심사, 경험 기록, 일정·예산·참여 조건 | 여행·취미·새로운 경험의 완료 기준 | 일정, 활동 기록, 결과물·회고 |
| 자기관리 및 습관 | 시간 사용, 반복 행동, 집중 시간, 실행 어려움 | 습관 실행률, 계획한 집중 시간, 회고 실천 | 수행 체크, 실제 시간, 중단 사유 |

건강 분야의 진단은 입력한 생활·운동 기록과 목표의 차이를 정리하는 자기평가로 한정한다. 금융 분야는 자산 현황과 목표를 위한 자금 계획부터 시작하며, 투자수익을 기본 전제로 계산하지 않는다. 사용자가 별도 수익률 등을 입력한 시나리오는 가정과 결과를 함께 표시한다. 분야 간 점수는 공통된 객관적 척도가 있다는 전제로 합산하지 않는다.

**진단 데이터에는 값뿐 아니라 출처와 시점을 저장한다.**

- 공통 프로필: 나이 또는 연령대(선택), 직업, 경력, 관심 분야, 현재 역량, 목표 성향.
- 가용 자원: 요일별 계획 배치 가능 시간대, 고정 일정, 예산, 이용 가능한 도구와 자료. 순가용 시간은 이 시간대에서 고정 일정 등 이미 예약된 시간을 한 번만 제외한 시간으로 정의한다.
- 측정 항목: 지표명, 값, 단위, 기준일, 출처, 자기 보고 여부, 첨부 근거.
- 평가 결과: 확인된 내용, 부족한 역량·자원, 미확인 정보, 다음 확인 과제, 적용한 평가 기준 버전.
- 자산·역량 상태는 새 값으로 덮어쓰기만 하지 않고 날짜별 기록을 보존한다.
- 입력하지 않은 정보는 ‘미입력’으로 남긴다. AI 추정으로 실제 값을 채우지 않는다.

자기평가, 실제 시험·결과물, AI 해석은 화면에서 구분한다. 검증되지 않은 자기평가 점수를 객관적 실력이나 타인 대비 백분위로 표시하지 않는다.

**목표는 수치형·결과물형·반복형을 구분해서 관리한다.**

공통 입력은 목표명, 주 분야와 관련 분야, 목표 이유, 기한, 우선순위, 단기·중기·장기 구분, 상위 목표, 완료 기준, 제약 조건이다. 기한을 나누는 기준은 설정에서 정할 수 있게 하고, 각 목표의 실제 마감일을 별도로 저장한다.

| 유형 | 기록할 기준 | 완료 판단 예시 |
|---|---|---|
| 수치형 | 시작값·현재값·목표값·단위·증가/감소 방향·기준일 | 사용자가 설정한 목표값 충족 |
| 결과물형 | 필수 구성과 검토 기준, 중간 성과, 증빙 | 포트폴리오 필수 항목 완성·사용자 확인, 자격 취득 기록 |
| 반복형 | 수행 요일, 주기, 횟수 또는 시간, 중단·예외 규칙 | 해당 기간의 약속한 수행 기준 충족 |

과제 완료와 최종 목표 달성은 분리한다. 준비 과제를 모두 마쳤다는 이유로 자격증 취득이나 취업 목표를 자동 완료 처리하지 않는다. 여러 목표에 기여하는 과제는 연결할 수 있지만, 실제 수행 시간은 한 번만 기록한다.

수치 목표는 방향·시작값·목표값·단위의 일치를 검사한다. 증가형 목표가 시작값보다 낮거나 감소형 목표가 시작값보다 높은 경우에는 이미 충족한 기준인지 방향 입력이 잘못됐는지 확인한다. 일정 범위 유지가 목적인 지표는 상·하한과 평가 기간을 저장하고, 해당 범위 충족 여부·기간 준수율로 판단한다. 증가·감소형 진행도 산식을 적용하지 않는다.

**계획 엔진은 모든 분야가 공유하는 시간·예산을 먼저 확인한다.**

1. 목표별 현재 상태와 완료 기준의 차이를 정리한다.
2. 필요한 중간 성과와 선행 과제를 구성한다. 부족한 내용은 추가 입력을 요청하거나 미확인으로 남긴다.
3. 과제별 예상 시간·비용·의존 관계·마감일을 기록한다. 예상치는 근거와 수정 가능 여부를 함께 표시한다.
4. 전체 목표의 주간 순가용 시간과 기간별 가용 예산을 공유 자원으로 배분한다. 고정 일정·휴식·기존 습관이 이미 시간대에서 빠져 있으면 다시 차감하지 않는다. 반복 습관을 고정 일정과 실행 과제에 동시에 연결한 경우에도 같은 시간은 한 번만 배정한다. 예산도 이미 확정한 지출을 중복 차감하지 않도록 정의한다.
5. 월간 중간 성과, 주간 과제, 가까운 날짜의 실행 과제로 구체화한다. 상위 계획과 하위 계획의 연결을 유지한다.
6. 가용 시간 초과, 일정 충돌, 순환 선행 관계, 기한 내 배치 불가를 검사한다. 총시간이 맞더라도 선후 관계와 고정 일정 때문에 배치가 불가능할 수 있다.
7. 불가능한 경우 기한·범위·투입 시간·우선순위의 조정안을 제시한다. 원래 목표와 수정안을 비교한 뒤 사용자가 적용한다.
8. 실제 소요 시간과 미완료 사유를 다음 계획에 반영한다. 완료 기록·과거 계획·변경 이유를 보존한다.

첫 버전은 설명 가능한 일정 배치 규칙으로 시작한다. 이후 필요하면 기한 우선·비용 우선·부담 완화 등 대안을 비교하는 기능을 추가한다. 조건을 만족하는 계획을 만들었다는 것만으로 전역적인 최적성이 증명됐다고 표현하지 않는다.

**실행·습관·회고는 계획 수정에 필요한 자료를 남긴다.**

- 오늘의 할 일: 우선순위, 예상 시간, 상위 목표, 완료 기준, 마감일을 표시한다.
- 실행 기록: 완료·부분 완료·미완료, 실제 시간, 결과물, 메모, 미완료 사유를 기록한다.
- 습관: 수행 예정일과 실제 수행일을 구분한다. 휴식일·일시중지·소급 입력에 대한 규칙을 정하고 연속 달성과 기간 실행률을 함께 표시한다.
- 일정: 고정 일정과 계획 과제를 구분하고 반복 일정, 겹침, 날짜 변경을 처리한다.
- 회고: 잘한 점·어려웠던 점·원인·개선 행동을 기록한다. 개선 행동을 다음 계획에 연결한다.
- 알림: 초기 제안은 앱 실행 중 알림과 재실행 시 놓친 일정 표시다. 창 닫기 후 상주, 완전 종료·절전 상태에서의 알림은 별도 요구로 확정한다.

**성과 화면은 실행률과 결과 지표를 나누어 보여준다.**

| 표시 항목 | 제안하는 내부 정의 | 함께 표시할 조건 |
|---|---|---|
| 기간 과제 실행률 | 기간 내 수행 예정 과제 중 완료한 과제의 비율 | 기간, 부분 완료 처리, 취소·제외 규칙 |
| 습관 실행률 | 수행 예정 기회 중 수행 기준을 충족한 비율 | 쉬는 날·일시중지 처리, 측정 기간 |
| 수치 목표 진행도 | 증가형은 `(현재값-시작값)/(목표값-시작값)`, 감소형은 `(시작값-현재값)/(시작값-목표값)`을 기준으로 계산 | 화면 진행 막대는 0~100% 범위로 표시하되 원래 값과 퇴보·초과 달성은 별도 유지. 분모가 0이면 별도 완료 판정 |
| 결과물 목표 진행도 | 사전에 정한 필수 중간 성과의 완료 비율 | 중간 성과·가중치, 최종 증빙 확인 여부 |
| 분야별 변화 | 같은 지표의 현재값과 과거값 비교 | 단위·기준일·측정 방식, 금액은 통화 |

위 산식은 프로그램 운영을 위한 제안이며 검증된 종합 역량 평가식이 아니다. 시작 시점부터 목표 기준을 충족했거나 시작값과 목표값이 같은 수치 목표는 해당 산식을 적용하지 않고 현재값으로 완료 기준을 직접 확인한다. 수행 예정 항목이 없어 실행률의 분모가 0이면 ‘해당 없음’, 필요한 입력값이 빠졌으면 ‘정보 부족’으로 표시한다.

첨부 이미지의 원형 ‘전체 성장률’은 첫 버전에서 ‘목표 종합 진행도’ 등 의미가 명확한 이름으로 바꾸는 것을 권장한다. 사용하는 목표, 가중치, 제외 항목과 기준일을 공개해야 한다. 목표 추가·삭제·완료 기준 변경 때문에 지표가 변한 경우 실제 성과 변화와 구분한다. 서로 다른 목표 구성을 사용한 두 시점의 종합 점수를 그대로 성장률로 비교하지 않는다.

**화면은 참고 이미지의 분위기를 적용하고 행동 우선순위를 명확히 한다.**

왼쪽 메뉴는 대시보드, 나의 프로필·진단, 목표, 로드맵, 오늘의 할 일, 성장 분석·회고, AI 코치, 설정으로 구성한다. 분야 선택은 목표·프로필·분석 화면의 공통 필터로 제공한다.

- 대시보드 상단: 오늘 할 일, 지연 과제, 이번 주 가용 시간 대비 계획 시간, 가까운 마감일.
- 목표 카드: 분야, 목표명, 실제 현재값·목표값 또는 완료 기준, 진행도, 다음 중간 성과, 기한, 지연 사유.
- 로드맵: 중간 성과와 선후 관계, 월·주·일 전환, 과제 수동 수정, 변경 전후 비교.
- 성장 분석: 기간별 실행과 분야별 성과를 나란히 표시하고 비교 기준을 설명한다.
- AI 코치: 확인한 근거, 부족한 정보, 제안 이유, 변경 영향, 적용 버튼을 표시한다.
- 설정: 시간·예산, 테마, 알림, 백업·복원, 외부 AI 전송 항목, API 키 설정을 관리한다.

어두운 배경·분야별 강조색·둥근 카드·사이드바를 참고하되, 작은 글씨와 과도한 장식은 조정한다. 사용자가 글자 크기를 조절할 수 있게 하고 키보드 이동, 창 크기 변경, Windows 배율과 macOS 화면에서 가독성을 확인한다. 참고 이미지와 동일한 모양을 구현했다고 전제하지 않으며 화면 시제품으로 확인한다.

**기술 기본안은 Python + PySide6 + SQLite다.**

사용자의 Python 경험을 활용하고 핵심 로직을 한 언어로 유지하는 설계 제안이다. PySide6는 Qt 6의 공식 Python 바인딩이다. [Qt for Python 공식 문서](https://doc.qt.io/qtforpython-6/)

| 역할 | 제안 | 구현 시 확인할 내용 |
|---|---|---|
| 화면 | PySide6의 Qt Widgets를 우선 검토 | 사이드바·카드·입력 폼·테마 시제품, 고해상도 배율 |
| 진단·계획·분석 | UI와 분리된 Python 모듈 | 입력 검증, 일정 계산, 집계 규칙, 설명 가능한 결과 |
| 저장 | SQLite와 Python `sqlite3` | 트랜잭션, 날짜·단위·금액 처리, DB 구조 변경, 스레드별 연결 정책 |
| AI·검색 | 공급자별 연결 모듈 | 인증, 요청 취소·시간 제한·실패, 응답 검증, 검색 근거 저장 |
| 그래프 | Qt 화면에 연동할 그래프 도구 선정 | 작은 시제품에서 한글·테마·실행 파일 호환 확인 |
| 실행 파일 | PyInstaller를 우선 검토 | 두 OS 각각에서 빌드·실행·저장·복원 확인 |
| 개발 관리 | Git, 프로젝트별 가상환경, 의존성 버전 고정 | 코드 변경 이력, 재현 가능한 설치·빌드 |

SQLite는 별도 데이터베이스 서버 없이 파일에 데이터를 저장하며, Python은 `sqlite3` 인터페이스를 제공한다. [Python 공식 문서](https://docs.python.org/3/library/sqlite3.html)

PyInstaller는 Python 앱과 의존성을 묶을 수 있지만 교차 컴파일러가 아니므로 Windows와 macOS용 빌드를 각 환경에서 준비해야 한다. [PyInstaller 공식 문서](https://pyinstaller.org/en/stable/)

Python·PySide6·패키징 도구의 버전은 호환되는 조합을 시제품으로 확인한 뒤 고정한다. AI 요청과 자료 검색, 큰 백업 작업은 화면을 멈추지 않도록 별도 작업으로 처리한다. UI 변경은 Qt의 실행 모델에 맞추고, DB 연결은 작업 간 공유 방식을 명시해 처리한다.

**핵심 데이터 구조는 화면과 분리한다.**

다음은 개념 모델이며 확정된 테이블 명세가 아니다.

| 데이터 | 핵심 내용 |
|---|---|
| 프로필·가용 자원 | 현재 경력·역량, 시간·예산, 사용자 설정 |
| 분야·지표 정의 | 분야명, 지표 단위·방향, 평가 기준 버전 |
| 상태 기록·진단 | 날짜별 값·출처·근거, 확인된 부족 사항 |
| 목표·중간 성과 | 목표 유형·완료 기준·기한·우선순위, 상위 관계 |
| 과제·선행 관계 | 예상 시간·비용, 완료 기준, 연결 목표, 의존성 |
| 일정·실행·습관 | 계획 일시, 실제 수행, 반복 규칙, 예외일 |
| 회고·계획 변경 | 회고 내용, 계획 버전, 변경 전후와 이유 |
| 자료·AI 제안 | URL·발행일(확인 가능 시)·확인일, 근거 내용, 제안 상태 |
| 첨부 파일·백업 정보 | 앱 내부 상대 경로, 파일 목록, 백업 시각, 형식 버전 |

자산 금액은 통화와 함께 정밀도를 정해 저장한다. 날짜만 의미하는 마감일과 시각이 있는 알림은 구분하고, 반복 일정과 통계는 사용자의 시간대 기준을 일관되게 적용한다. DB와 첨부 파일은 프로그램 설치 위치와 분리된 사용자 데이터 폴더에 저장한다.

**AI는 진단 설명과 경로 초안을 제안하고, 앱이 계산과 변경을 검증한다.**

입력 범위를 선택한 사용자 자료와 확인한 외부 자료로 제한한다. 결과는 확인된 사실, AI 해석·가정, 정보 부족, 권장 행동, 참고 출처로 구분한다. AI가 만든 과제는 연결 목표·완료 기준·예상 시간·출처 등 구조화된 형식으로 받는다.

적용 전에는 필수 값, 유효한 목표 연결, 선행 관계의 순환, 가용 시간·예산 초과, 과거 완료 기록 변경 여부를 프로그램이 검사한다. 사용자에게 변경안을 보여준 다음 적용하고 기록을 남긴다. 인터넷 단절이나 응답 오류가 발생해도 기존 계획 열람·기록·수동 수정은 계속 사용할 수 있어야 한다.

검색 자료는 출처와 발행일(확인 가능 시), 확인일을 보관한다. 검색 문서 안의 명령을 앱 동작 지시로 받아들이지 않는다. 자료를 못 찾으면 출처를 만들지 않고 정보 부족을 표시한다. API 키는 OS 보안 저장 기능과 연동하고 로그·일반 백업에서는 제외한다. 자산·건강·이력 등 외부 전송 항목은 사용자가 선택하고, 필요한 최소 자료만 전송한다.

AI·검색 공급자, 모델, 사용 예산, 호출 빈도는 미정이다. 자동 반복 호출은 기본값으로 두지 않고 사용량·비용 확인 방법과 한도 도달 시 동작을 정한다.

**Windows와 Mac 사이에는 일관된 백업 묶음을 이동한다.**

백업 형식은 DB 스냅샷, 첨부 파일, 형식 버전과 파일 목록을 묶는 방식으로 제안한다. 실행 중인 SQLite 데이터의 일관된 복사에는 SQLite의 백업 기능 등을 사용한다. [SQLite 백업 공식 문서](https://www.sqlite.org/backup.html)

복원 전에 앱 형식 버전·파일 목록·데이터 유효성을 확인하고 현재 데이터를 자동 백업한다. 첫 버전은 전체 복원을 기본안으로 하고, 두 기기에서 따로 수정한 기록의 병합은 이후 기능으로 둔다. 복원은 기존 데이터를 교체한다는 영향을 미리 보여준다. 첨부 파일은 절대 경로에 의존하지 않도록 저장하고, API 키는 복원한 기기에서 다시 설정한다.

자산·건강 정보가 포함되므로 백업 암호 보호 방식도 구현 전에 결정해야 한다. 보호할 경우 검증된 암호화 도구를 사용하고, 비밀번호와 복구 방식을 함께 설계한다. 아직 백업이 자동으로 암호화되거나 보호된다고 전제하지 않는다.

**1인 개발은 공통 엔진을 먼저 완성한 뒤 분야별 깊이를 늘린다.**

| 단계 | 구현·정의 범위 | 완료 확인 |
|---|---|---|
| 1. 명세·작은 시제품 | 6분야 입력 항목, 지표·완료 기준, 화면 흐름, Qt 대시보드 시제품, 양쪽 OS 패키징 확인 | 대표 입력·목표·화면과 실행 환경이 맞물리는지 확인 |
| 2. 저장·핵심 흐름 | 프로필, 6분야 기초 기록, 목표, 과제, 수동 수정, 저장·백업·복원 | 목표 등록→실행 기록→재실행→다른 OS 복원 |
| 3. 공통 성장 경로 | 근거를 표시하는 기초 진단, 중간 성과, 시간·예산·의존성 검증, 월·주·일 계획, 습관 | 여러 분야 목표의 일정 충돌과 불가능한 계획을 확인 가능 |
| 4. 코칭·분석 | AI 경로 초안, 검색 근거, 실행·성과 분석, 회고, 변경안 확인·재계획 | 근거·정보 부족·변경 이유를 확인하고 적용 가능 |
| 5. 안정화·확장 | 알림, UI 조정, 오류 복구, DB 변경·복원 검증, 분야별 진단 고도화 | 양쪽 OS에서 정의한 시나리오 통과 |

6개 카테고리는 초기 데이터 구조와 목표 관리에 모두 포함한다. 분야별 정밀 평가·자동 수집은 우선순위에 따라 확장한다. 은행·증권 자동 연동, 웨어러블 연동, 양방향 캘린더 연동, 두 기기 실시간 동기화는 추가 개발 항목으로 별도 추정한다.

단계 2는 수동 입력·계획·실행·복원이 가능한 기본판이다. 단계 4까지 연결한 버전은 진단·성장 경로·AI·재계획을 포함하는 통합판으로 구분한다.

**통합판은 입력부터 재계획·복구까지 검증한다.**

- 자기평가만 있는 항목과 증빙이 있는 항목이 구분된다.
- 목표별 완료 기준과 과제별 완료 기준이 연결된다.
- 6분야 목표가 한 주의 시간·예산을 중복 배정받지 않는다.
- 한 과제가 여러 목표에 기여해도 실제 시간은 중복 집계되지 않는다.
- 일정 합계가 맞더라도 선행 관계나 고정 일정 때문에 불가능하면 표시된다.
- 목표 변경만으로 진행도가 오른 경우 실제 성과 변화로 오해하지 않게 표시된다.
- 습관의 휴식일·일시중지·누락과 반복 일정이 정한 규칙대로 처리된다.
- AI 실패·인터넷 단절 상태에서 기존 계획과 기록을 사용할 수 있다.
- 재계획이 완료 기록을 지우지 않으며 이전 계획과 변경 이유를 확인할 수 있다.
- Windows와 Mac에서 한글 경로, 창 배율, 날짜·시간, 설치·실행·알림을 확인한다.
- Windows→Mac 및 Mac→Windows 복원에서 데이터와 첨부 파일이 유지된다.
- 잘못되거나 호환되지 않는 백업 복원 실패가 현재 데이터를 손상시키지 않는다.

이 목록은 앞으로 수행할 검증 조건이다. 현재 구현이나 시험을 완료한 항목은 없다.

**다음 명세에서 확정할 항목이 남아 있다.**

분야별 최초 입력 항목과 평가 기준, 단·중·장기의 기본 기간, 전체 진행도의 표시 방식, AI·검색 공급자와 예산, 최소 지원 OS 및 Mac 프로세서 범위, 앱 종료·절전 상태 알림 요구, 백업 암호 보호 방식이다. 상세 개발 기간과 비용을 산정하려면 이 범위와 주당 개발 가능 시간에 대한 정보가 더 필요하다.
